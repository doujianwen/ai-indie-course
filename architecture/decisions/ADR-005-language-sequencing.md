# ADR-005 课程语言时序：中文先跑通（执行路径 / 源），英文做本地化（目标市场）

- 状态：已采纳（Accepted）
- 日期：2026-08-11
- 提出：主理人拍板（基于第一性原理推敲「先中文跑通 vs 先英文跑通」）

---

## 背景（Context）

在 ADR-004 之后，语言策略上曾混淆了**两个独立轴**：

1. **目标市场轴（卖给谁）**：英文 / 海外学员。
2. **执行路径轴（怎么造）**：用哪国语言先把课程做出来并验证。

此前在 `architecture/07-m8-m9-m10-lesson-scripts.md` 头部写成 "English (canonical) — the course is English-main"，把"目标市场=英文"直接等同于"执行=英文"。这是错的：它把最大风险（海外需求证伪）放在了投入最重、最晚的位置暴露。

主理人经建议后采纳"先中文跑通，再做英文"的时序。本 ADR 把两轴解耦，修正 07 头部的措辞偏差。

---

## 决策（Decision）

**1. 目标市场（who you sell to）= 英文 / 海外学员。**
bookconv 本身就是英文产品，课程教的是「怎么做海外产品」。英文版是最终要**验证真实需求**的产品形态，不是可选项。ADR-004 的"英文主线"措辞应 reinterpret 为「目标市场 = 英文」，其范围升级（M8/M9/M10 提至 V1）完全保留。

**2. 执行路径（how you build）= 中文先跑通（中文 = 原型 / 单一事实源）。**
- 中文母语者制作速度、口播质量、剪辑返工成本是英文的 2–3 倍优势；"跑通"整条流水线（脚本→录制→剪辑→发布→售卖）中文最快。
- 最大的未知是「课程内容教得是否有效」，不是「用哪国语言」。M8/M9/M10 在中文里验证+修正一次就够了——中文不行，英文也不会行（同一套内容）。
- 英文 = **已验证产品的本地化**（翻译 / 配音），风险远低于「从零用英文硬造再祈祷海外用户喜欢」。中文 IP 资产被复用，不是浪费。
- 与现有仓库基线对齐：PRD / 架构 / README / ADR / 07 都是中文底子，直接开干，不必先花力气翻英文。

**3. 仓库语言定位（解耦后）**
- 现有中文规划文档（PRD/架构/README/ADR/07）= **内部源（single source of truth for content）**，不急着翻英文。
- 现有 `07-m8-m9-m10-lesson-scripts.md` 英文版 = **本地化目标参考（localization reference）**，待中文课程跑通后由已验证内容翻译/配音产生，而非重写。其头部 "English (canonical) / English-main" 措辞作废，改为"英文 = 本地化目标（见 ADR-005）；执行优先以中文为工作源"。

**4. 立即动作（sequencing 落地）**
- 用**中文 mini 版（免费小课 / 直播）先跑一轮**，验证：教学是否立得住 + 转化路径是否通。几乎零成本。
- 验证 OK 后，再投入英文全量制作（可配翻译/配音，把中文当作 source）。

---

## 后果（Consequences）

**正向**
- 跑通速度最快；内容先在中文验证+修正，英文生产时内容已定型，风险最低。
- 中文 IP 资产复用；与现有中文规划文档基线对齐，无需先翻英文（呼应此前"选项 B：中文留作内部源"）。
- 把"海外需求证伪"这一最大风险，放在更晚、投入更轻的节点暴露——对单人创作者是最优顺序。

**负向 / 风险**
- 中文先跑通，**先验证的是中文市场，不是海外需求**。这是真实代价。
- 但课程内容本身就是「怎么做海外产品」（bookconv 即英文站），中英文教同一套能力；英文版紧接跟上，海外目标不受影响。
- 海外需求只有英文版真正上线才测得到——这点无论中先英后还是英先中后都成立；区别只是英先中后会把"需求证伪"放在更早、投入更重处暴露。

**对齐**
- 不推翻 ADR-004 的范围升级，只澄清其语言轴。
- `README.md` 关键决策记录 #8（本 ADR）
- `architecture/07-m8-m9-m10-lesson-scripts.md` 头部措辞修正（英文 = 本地化目标，中文 = 执行源）
- 后续 M8/M9/M10 **实际录制脚本以中文为工作源**；英文版在其后由已验证内容产出
