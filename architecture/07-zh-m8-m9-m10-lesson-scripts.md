## 0. 真实数据脱敏 Master Spec（三模块通用，单条铁律）

在镜头前使用 bookconv 真实数据只有一条规则：既要**不泄露创作者私有分析数据**，又要**避免数字看起来像"成功证明"而触发 Google 规模化内容政策**。

### 0.1 永远可以展示（无需打码）
- **方法论 / 结构 / 架构**：内容簇地图、单源内容注册代码、内链图谱、sitemap/llms.txt/robots 配置、代码片段、verifyConversion 流程。
- **相对 / 比较事实**：「簇 A 排 ~21 位，分散页排 ~69 位」——展示*差距*，背后绝对展示量打码。
- **趋势形状 & 诊断路径**：「展示量先升后平」「query 覆盖矩阵有 3 个缺口」——展示*形状*，坐标轴数字打码。
- **时间用阶段而非日期**：「上线后头 ~2 周」——绝不暴露能让观众推算站点年龄的真实日历日期。

### 0.2 必须打码（绝对值 → 占位）
| 数据类别 | 镜头前规则 |
|---|---|
| GSC 展示 / 点击 / CTR | 模糊或替换为 `N 次展示`、`0 点击（早期）`；保留*曲线*与*相对位置*。 |
| GA4 用户 / 会话 / 事件 | 绝对计数打马赛克；只展示漏斗*形状*与*流失率%*。 |
| 收入 / 订阅数 / 金额 | 绝不展示。只以"早期、尚未规模化变现"口播带过。 |
| 确切上线日期 / 站点年龄 | 说"几周大""新域名"。不展示真实日期。 |
| PII（邮箱 / IP / 含名的文件名） | 全打码。 |
| 负面暴露项目的竞品细节 | 避免以会 dox 项目的方式点名失败实验。 |

### 0.3 怎么打码（制作手法）
- GSC/GA4 截图：在数字单元格上叠**马赛克 / 模糊层**；保留标签、图表形状、坐标轴*方向*。
- 直播演示：导航到真实看板但把数字**放大模糊**，或在剪辑里用脱敏克隆截图。
- 口播：教*诊断过程*（"我是怎么发现覆盖率是瓶颈的"），不教*分数*（"我只有 287 次展示"）。
- 这是已批的**决策#3**（截图隐去绝对数值）扩展至全部三个模块。

### 0.4 「诚实账本」口径（选择性披露，Q2）
- 把「0 点击 → 怎么诊断」当作**所有新站的普遍规律**来教，而不是 bookconv 的耻辱。
- 信息："新域名头几周 ~0 点击是常态，不是失败。**关键是你下一步查什么**。"——这会让同样在 0 的海外学员产生信任。

## M8 — 内容策划系统（Module 8）

**为什么进 V1**：内容是产品被发现的真正抓手；bookconv 有真实 87 页体系可教，无需编造。
**使用的真实资产**：87 内容页（36 博客 + 21 指南 + 30 转换页）、185 条编辑内链、通用锚文本 0 条；`docs/content/一页吃整簇策略.md`；`src/lib/internal-links.ts`；`src/data/{blog,guides,content}`。

### M8-L1 — 「一页吃整簇」（核心原则）
- **目标**：学员能判断*何时把*关键词变体合并到一页、何时拆分。
- **素材（脱敏）**：`azw3 vs mobi` 簇（一页，~29 展示，位置 ~21）vs 分散的 `mobi→epub` 页（位置 ~69）；西语版最佳 ~15。
- **口播稿提纲（中文，讲师视角）**：
  1. **钩子**：「我曾差点为一个意图建 6 个页面。这是新手最常犯的错。」
  2. **原则**：同意图变体 → 一个权威页；合并，不要乘法式复制。
  3. **现场**：打开 `docs/content/一页吃整簇策略.md`，展示簇决策表（对比 X vs Y / 选择 X or Y / 疑问 does X work / 场景 for kindle / 多语言）。
  4. **证据（打码）**：一个簇页 ≈ 21 位；分散版 ≈ 69 位。展示*差距*，模糊计数。
  5. **口诀**：「点进来的搜索者想要同一个答案吗？是 → 合并。否（如 `convert X to Y` 交易意图 vs `X vs Y` 信息意图）→ 拆分。」
- **演示**：把一个假想分散集合重命名为一个簇页；展示 H1 + 对比 `<table>`（featured-snippet 目标）。
- **时长**：~12 分钟。**验收**：学员能对 5 个给定关键词做合并/拆分判断并给出理由。
- **🎬 完整逐字稿（可直接念）**：`07-zh-m8-l1-full-script.md`（含开场钩子、转场、镜头/演示提示、结尾 CTA、脱敏检查点，可用于中文 mini 试水）。

### M8-L2 — 单源内容注册
- **目标**：学员能新增内容而不破坏 sitemap/RSS/LLMs。
- **素材**：`src/data/blog/*.ts` 注册 + `index.ts`；自动派生流（列表 → sitemap → rss）。
- **口播稿**：展示注册文件；新增一篇博客条目；重新构建；验证它出现在 sitemap.xml 与 RSS 中，无需手动改多处。强调「一次编辑，万物派生」。
- **时长**：~10 分钟。**验收**：学员在 stub 上复现新增内容流程。

### M8-L3 — 内链架构
- **目标**：学员能把页面织成聚拢权重的链接图谱。
- **素材**：`src/lib/internal-links.ts` helper；185 条链接图谱；P0/P1/P2 修复日志（修 2 断链、接通 指南↔博客↔转换 三角）。
- **口播稿**：展示 helper + 内链审计前后对比；演示修一条死链、加一条编辑锚文本（不用"点击这里"这类通用文案）。
- **时长**：~11 分钟。**验收**：学员审计一个样例站点并列出 3 条链接修复。

## M9 — SEO / GEO 运营增长（Module 9）

**为什么进 V1**：海外学员需要*被发现*；bookconv 的 GEO/SEO 配置真实且可教。
**使用的真实资产**：`public/llms.txt`、`robots.txt`（放行 GPTBot/ClaudeBot/CCBot）、`next.config.ts`（sitemap 派生、compress）、`scripts/seo-critic.mjs` 门禁、`src/app/sitemap.ts`、hreflang as-needed 中间件、真实 GSC/GA4 诊断。

### M9-L1 — 技术 SEO 底座（sitemap / llms.txt / robots / hreflang）
- **目标**：学员交付可被爬取、可被 AI 索引的底座。
- **口播稿**：展示自动派生的 sitemap；打开 `llms.txt` 解释 GEO（让 LLM 爬虫读结构化摘要）；展示 `robots.txt` 放行 GPTBot/ClaudeBot/CCBot；解释 `localePrefix as-needed`（英文无前缀、西语 `/es`、`/en/*`→301 重写），canonical 一律只由页级输出。
- **演示**：跑 `seo-critic.mjs`（退出码门禁）证明底座在 CI 里被强制。
- **时长**：~13 分钟。**验收**：学员列出 4 个技术支柱并说明各自为什么重要。

### M9-L2 — GSC 实战：诊断 0 点击（选择性披露）
- **目标**：学员知道新站没流量时的*检查清单*。
- **素材（脱敏）**：GSC 覆盖率、排名、query 覆盖、技术 SEO 标签页——展示*路径与形状*，打码绝对展示/点击。
- **口播稿**：「新域名，第 2 周 ~0 点击——正常。这是 4 步诊断：(1) 收录了吗？(2) 什么位置？(3) query 覆盖缺口？(4) 技术 SEO 卡点？」逐标签走一遍，打码数字，保留*决策树*。
- **时长**：~14 分钟。**验收**：学员能在自己的 GSC 上跑这 4 步审计。
- **📊 真实数据源（已就绪，可直接引用）**：`E:/一人公司/电子书格式转换站/ebook-converter/数据分析/bookconv-daily-trend-2026-08-13.html`（bookconv 真实 GSC 快照，导出日 2026-08-13，窗口 7/25–8/11，已带「教学案例·AI 实战课程」标签）。教学可用要点：**(a) 0 点击诊断叙事**——展示 716→但 0 点击，讲清"排名到位、缺 CTR"是真实瓶颈（标题/描述不吸点击），非内容差；**(b) 8/9 台阶式增长**——基线 ~19/天 → 8/9 起 ~132/天（+605% 已固化），讲"别因 0 点击恐慌，先看对指标"；**(c) 数据素养**——CSV 快照 vs Search Console API 逐日真值两口径对账、阈值压制「(其他)」桶。脱敏口径（§0）：绝对展示/点击数打码；可讲相对比较（+605%）、位置差距（#10 vs #69）、趋势形状（台阶）、西语页 #1 vs 英文同主题、0 点击诊断本身。该文件留在主站 `数据分析/`，课程仓不搬运（分仓约定）。

### M9-L3 — GA4 实战：行为与转化漏斗
- **目标**：学员衡量*用户做了什么*，而不只是流量。
- **素材（脱敏）**：GA4 自定义关键事件（文件上传 / 转换完成类，上线初期补建）；着陆页→上传→完成 漏斗；打码用户计数，保留流失率%。
- **口播稿**：展示事件配置；搭建漏斗报告；把流失解读为产品最大的杠杆点。
- **时长**：~12 分钟。**验收**：学员为自己的产品定义 2 个关键事件 + 一个漏斗。

### M9-L4 — 外链（ROI 优先，不滥用）
- **目标**：学员在不 spam 的前提下赚权威。
- **口播稿**：bookconv 先做完首页外链，再按 ROI 优先做内页外链；规则：「链接必须流价值，不操纵」。把内链审计当作*站内*一半，外链当作*站外*一半。
- **时长**：~8 分钟。**验收**：学员按 ROI 给 5 个外链目标排序。

## M10 — 防跑偏 / 第三视角纠错（Module 10）

**为什么进 V1**：借旧版 `ai-independent-dev` *correction-agent* 的**内核**（范围冻结 + 阶段验收 + 纠错清单）——**不是**它的多智能体外壳，**不是**它的虚构内容。这是阻止学员（和讲师自己）在错事上耗数月的模块。
**真实锚点案例**：一位 6 年经验 PM，花 ~3 个月给一个插件自研*编辑器*，而不是把插件做出来——教科书式跑偏。

### M10-L1 — 独立开发者为什么会跑偏（真实失败模式）
- **目标**：学员在跑偏*还没*花掉数月前就认出来。
- **口播稿**：讲真实案例（PM，3 个月耗在副工具上，产品零进展）。画出跑偏模式：模糊范围 → 闪亮子问题 → 忘了原目标。展示*情绪*拉力，不只是逻辑。
- **时长**：~9 分钟。**验收**：学员能说出 3 个跑偏预警信号。
- **🎬 完整逐字稿（可直接念）**：`07-zh-m10-l1-full-script.md`（含开场钩子、转场、镜头/演示提示、三个预警信号、结尾 CTA、脱敏检查点，可用于中文 mini 试水）。

### M10-L2 — correction-agent 内核（借来，剥壳）
- **目标**：学员在自己的工作流里装一个轻量"第三视角"。
- **口播稿**：解释旧项目的 3 机制内核，重新落地于现实：
  1. **范围冻结**——写下 v1 范围；任何新东西进"以后"清单，不进 v1。
  2. **阶段验收**——每个阶段有明确"完成当……"闸门（对应我们的 AC-1..AC-7）。
  3. **纠错清单**——周期性自问：「这还是原目标吗？我是不是在造造工具的工具？」
- **时长**：~10 分钟。**验收**：学员写下自己的范围冻结说明 + 纠错清单。

### M10-L3 — 打造你自己的「第三视角」
- **目标**：学员把防跑偏做成每周 10 分钟习惯。
- **口播稿**：演示一个可复制的每周范围审计模板：列出本周工作 → 每条打标「核心目标 / 相邻 / 跑偏」→ v1 阶段把跑偏压到 0。回扣 bookconv 自己的范围纪律（我们砍功能只为交付）。
- **时长**：~8 分钟。**验收**：学员在自己的当前项目上跑一次审计。

## 录制前脱敏检查清单（5 分钟，附在录制 SOP 后）

每次开录前逐条勾：
1. GSC/GA4 截图数字单元格已叠马赛克？保留标签与形状。
2. 口播里没有说出绝对展示/点击/用户/收入数字？
3. 没暴露确切上线日期或站点年龄？（用"几周大"）
4. 没有出现 PII（邮箱/IP/含名文件）？
5. 相对比较只讲差距、不讲绝对值？
6. 「诚实账本」口径到位：0 点击被讲成普遍规律，不是羞耻？
